HOW TO READ THIS DATA

Published signals describe configuration at scan time.

SPF, DMARC, mail routing, and DNSSEC findings describe published DNS configuration. Before the security.txt request, the collector makes a bodyless HTTP HEAD /, follows redirects, and records whether that response chain upgrades to HTTPS, plus selected server and security headers including HSTS. It then GETs only /.well-known/security.txt over HTTP, trying HTTPS only if HTTP fails before returning a response. The HEAD result describes observed redirect behavior; it does not simulate a browser's cached HSTS state. Format validity is separate from expiry freshness, and security.txt redirects and certificate validity are reported independently. Signed-file structure is checked without cryptographic verification. Response bodies and certificate details are processed in memory and discarded.

Likely mail services are inferred from role-specific hostname matches: outbound clues use SPF include/redirect targets, inbound clues use MX hosts, and reporting clues use DMARC or TLS-RPT destinations. Unmatched hostnames remain visible as Unclassified. These clues describe published configuration; they do not confirm actual message traffic.
